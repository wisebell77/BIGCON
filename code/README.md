## 2. 실행

```bash
python code/run_all.py
```
그다음 `code` 폴더에서 노트북을 10 → 20 → 30 → 40 → 50 → 60 → 70 → 80 순서로 실행한다(30은 20의 표를, 40·50·60은 30·40의 표를, 70은 20·30·40의 논리를, 80은 70의 최적 파라미터를 읽는다). 명령으로 돌리려면:
```bash
cd code && jupyter nbconvert --to notebook --execute --inplace 10_eda.ipynb 20_sensitivity.ipynb 30_vulnerability.ipynb 40_models.ipynb 50_longterm.ipynb 60_stores_map.ipynb 70_tuning.ipynb 80_algorithm.ipynb
```
70번은 모델 탐색 때문에 10분 안팎, 80번은 5분 안팎 걸린다.
09번(서울 외부 자료)은 큰 원본을 프로젝트 밖 `D:\Bigcon_data`(환경변수 `BIGCON_EXT`로 변경)에서 읽고, 추정매출-자치구는 열린데이터광장 Open API로 받는다. 인증키는 프로젝트 루트 `.env`의 `openapi_seoul`에 두며(제출하지 않음), 한 번 받은 뒤에는 보관된 원본 CSV를 다시 쓰므로(`--no-api`, run_all이 자동 판단) 키 없이도 재현된다. 원본 폴더가 없으면 09는 건너뛴다.
09b(기상청 단기예보 격자)는 `.env`의 `weather_api`(API허브 인증키)로 `python code/09b_kma_forecast.py`를 한 번 돌려 원본(gzip 텍스트, 약 5,900개)을 받아 두고, run_all에서는 `--build`로 보관된 원본만 정리한다. 09c(관광데이터랩)는 받아 둔 zip만 읽는다. 85번 노트북은 09b 결과가 있어야 돈다.
필요 패키지: pandas, numpy, pyarrow, statsmodels, scipy, scikit-learn, lightgbm, matplotlib(맑은 고딕), nbformat/nbclient(명령 실행 시). 전체 실행 시간은 5분 안팎.

## 4. 전처리 결정

- 분석 대상(`in_scope`): 소비성 업종(세금·보험·통신요금·PG·등록금·상품권 제외) 중 거래일 비율 95% 이상, 하루 평균 20건 이상인 지역×업종 141개(강남 77, 춘천 64). 그중 대면소비 업종군(음식점·카페·주점·식품·패션·생활소매·대형유통·숙박·여가·개인서비스) 105개가 상권 분석의 기본 범위다. 컴퓨터/소프트웨어·방문판매·체인점은 성격이 불명확해 대면소비에서 뺐다.

## 5. 분석 방법

- 기준선(평상시): 각 날 로그 매출 − 같은 요일 앞뒤 1·2주 평균. 특별일은 기준선에서 뺀다. EDA와 분류 라벨에 쓴다.
- 민감도(20): 시리즈마다 `log(매출) = 요일 FE + 주 FE + 이벤트 더미 + 비 전날·다음 날 + 특별일 통제`. Newey-West(7일) 표준오차. 업종군·지역 값은 역분산 가중 평균(정밀도 기준)과 매출 가중 평균(경제적 크기 기준)을 같이 보고한다. 시간대 패널은 그 시간대의 비·더위를 쓴다. 연령군·거주지(지역민/외지인)별도 같은 방식.
  - 기준선 편차 방식은 이웃 주에도 비가 오면 효과가 작게 나온다(9월). 회귀가 본 추정치다.
- 취약 지수(30): IPCC 위험 틀. 민감도(회귀 계수를 경험적 베이즈로 지역 평균 쪽으로 축소, 증거 규칙: 자체 p<0.10 또는 지역 평균 z<−1.96일 때만 사용) × 노출(시간대 매출 비중 × 이벤트의 시간대 분포, 폭염·열대야는 60대+ 고객 비중 × 지역 유동인구 60대+ 비중 추가) × (1 − 적응능력: 반등, 소상공인 여부, 외지인 비중). 윈저화 최소-최대 정규화, 가중 기하평균(0.5/0.25/0.25). 대면소비 안에서 상위 25% 취약, 상위 10% 매우 취약. 가중치·결합 방식을 바꿔도 순위 상관을 확인한다.
- 피해 규모(30): 이벤트일 매출 × (exp(−β)−1), 감소가 확인된 시리즈만. 하루당 평균 손실도 저장한다.
- 모델(40): (A) LightGBM으로 '4주 같은 요일 평균 대비 편차'를 예측(달력·7일 이상 지난 매출·업종 구조·날씨), 월 단위 교차검증과 7~10월→11~12월 앞으로 예측. 비교 기준선은 4주 같은 요일 평균과 날씨 없는 모델. 해석은 내장 SHAP. (B) 이벤트일에 10% 이상 감소할지 분류(LightGBM, 날짜 GroupKFold). (C) 우선순위 = 경보 확률 × 예상 손실(그 요일 평상 매출 × 민감도), 소상공인 업종 한정 목록과 전체 목록.
- 상가·지도(60): 업소당 지표 = 지역×업종 값 / 업소 수. 동별 호우 하루 예상 손실 = Σ_업종 (동 업소 수 / 지역 업소 수) × 지역×업종 호우 하루 손실(30번). 취약 업소 = 취약·매우 취약 등급 업종의 업소. 같은 지역·업종이면 동이 달라도 업소당 민감도·매출이 같다고 가정한다(카드가 시군구 단위라 동별 민감도는 측정 불가).
- 튜닝(70): 취약 지수를 216가지 설정(가중치 6 × 결합 2 × 윈저화 2 × 증거 규칙 3 × 등급 컷 3)으로 다시 만들어 순위 상관·취약 집합 자카드·"설정 중 취약으로 분류된 비율"을 본다. 예측 모델은 하이퍼파라미터 30개 조합 무작위 탐색(월 단위 교차검증), Ridge·지역별 분리 모델 비교. 분류 모델은 30개 조합 + 로지스틱·등방 보정·비용 기준 임계값. 손실 직접 예측(LightGBM으로 이벤트일 감소율을 예측)과 회귀 β 방식을 날짜 GroupKFold로 비교.
- 알고리즘(80): `priority.py`. 점수 = 예상 손실 = Σ_시간대 (그 요일·시간대 평상 매출 × (1 − exp(β_시간대))) + 폭염·열대야 일 β 손실. β_시간대는 비가 5mm 이상(또는 1~5mm) 온 시간대의 시리즈별 민감도(경험적 베이즈 축소 + 증거 규칙). 경보 확률 p는 점수에 곱하지 않고 경보 여부(임계값)로만 쓴다. 비교용으로 p × 예상 손실, 사후 기대 β(E[min(β,0)]), 일 β, 확률 보정 손실(요일 평상 매출 × (1 − exp(−E[−dev | p]))) 점수를 같이 낸다. 백테스트는 한 달씩 빼고(분류기·β·평상 매출 모두) 학습해 뺀 달의 호우일(손실이 있는 이벤트)에 적용, 실제 손실(기준선 편차 기반, dev 2~98% 윈저화)과 비교. 시나리오 격자는 전체 자료로 학습한 최종 모델. 이벤트 발생 확률은 1991~2025 일자료에 `logit(p) = 계절 조화항(3차) + 연도 추세`를 1991~2020으로 학습해 2021~2025로 검증(Brier), 2026년 날짜별 확률 × 이벤트 하루당 손실로 기대 손실 캘린더.
- 장기(50): 연간 지표의 선형 추세(10년당 변화, p값)와 2025년 순위. 특보·이상기후 기준으로 20번과 같은 회귀를 다시 돌려 정의에 따른 차이를 본다. 시나리오 손실 = 시리즈별 '이벤트 하루당 손실'(30번) × 7~12월 이벤트 일수. 이벤트 일수는 장기 자료의 공식 일자료 집계에 '우리 2025 일수 / 공식 2025 일수' 비율을 곱해 정의 차이(영업시간 강수, AWS/ASOS, 밤 최저기온)를 흡수한다.

## 8. 한계

- 카드 기간이 6개월이라 민감도는 2025년 하반기 값이다. 장기 추세와 평년 대비는 서울·춘천 ASOS 1991~2025로 봤지만 두 지점뿐이라 전국 추세(기상청 113년 보고서)와 함께 읽어야 한다. 태풍 직접 영향 사례가 없고 한파는 3일이다.
- 특보 이력은 2014년 이전 파일이 깨져 일부 해제 통보가 빠졌고, 폭염특보는 2008년 시작·2020년 체감온도 기준 전환, 서울 권역 세분은 최근 자료만 있어 연도 비교에 제도 변화가 섞인다.
- 카드 데이터가 시군구×업종 단위라 동·블록 단위 민감도는 측정할 수 없다. 동 단위 지도는 지역×업종 손실을 업소 수 비례로 나눈 값이다. SK는 월 단위라 날씨 반응을 직접 재지 못한다(주최 측에 일별 제공 여부 문의 예정). 서울 생활인구는 일·시간 단위지만 집에 있는 주민을 포함해 비 오는 날에도 거의 변하지 않으므로(09 점검) 노출 구조 용도로만 쓴다. 춘천은 같은 자료가 없다.
- 상가정보는 2026년 6월 기준(카드는 2025년 하반기)이고 신한카드 가맹점이 아니라 등록된 전체 업소다. 폐업 반영이 늦을 수 있고, 카드 업종과 1:1이 아닌 매핑(골프 연습장 등)이 있어 업소당 값은 대략적인 수준이다. 2025년 12월 기준 파일이 있으면 바꿔 끼우면 된다(파일명 YYYYMM만 다르면 코드 수정 없음).
- 소비쿠폰·상생페이백 교란은 주 고정효과와 특별일 통제로 흡수했지만 지급 직후 며칠의 효과가 남을 수 있다(쿠폰 직후 2주 제외 추정과 비교해 둠).
- 폭염 효과는 '같은 주의 덜 더운 날' 대비라 날씨가 좋은 날의 효과가 섞인다. 폭염 손실 추정은 보수적이다.
- 단기예보는 격자점 하나(강남구청·춘천시청 부근 5km 격자)의 값이고, 체감온도·습도 예보는 쓰지 않았다. 관광데이터랩은 월 단위라 날씨 반응을 재지 못하고 춘천의 외지인 의존 구조를 보여 주는 용도다. 온열질환은 강원도 전체 환자를 춘천 기온과 맞춘 참고값이다.
- 손실액은 확인된 감소만 더한 값이라 과소일 수 있고, 열대야 손실은 한 시리즈에 의존한다.
